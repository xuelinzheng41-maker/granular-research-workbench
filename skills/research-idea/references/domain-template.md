# 领域层模板：怎么写你自己的 domain-*.md

> 换研究方向时复制本文件，改名 `domain-<方向>.md`，填内容。**SKILL.md 不用动。**
> 有知识库时用 `kb.py stats` 校准数字；没有知识库也能写（去掉统计数字即可）。

## 必填六节

| 节 | 内容 | 判断标准 |
|---|---|---|
| 1 空位形态 | 这个领域"缺口"长什么样（3~5 类） | 每类要给"怎么判断是空的"的可操作判据 |
| 2 审稿人三连问 | 这个领域最常被拒的三个理由 | 每条要能在写 idea 时自答 |
| 3 证据惯例 | 什么算证据、什么不算 | 要区分"能写进正文"和"只能算说明" |
| 4 伪创新清单 | 常见但会被拒的做法（4~5 条） | 每条要能一眼识别 |
| 5 kill 判据 | 哪个实验/反例失败即作废（K1..K4） | 阈值必须可核验 |
| 6 分界 | 与相邻研究类型的分界 | 避免 claim 越界 |

## 写作要求

- **具体**：写"对手预算要对等"，不要写"要做公平比较"
- **可核验**：每条判据都要能用一句话验证真假
- **带反例**：说明某个做法为何是伪创新时，给一个具体句式
- **别抄综述**：领域文件是操作手册，不是背景介绍

## 自检

```bash
# 有知识库时，用 stats 校准"哪个族拥挤"
python scripts/kb.py stats
```

写完问自己：**一个新生按这份文件能判断"这个空位值不值得做"吗？** 如果不能，就是写得太抽象。
