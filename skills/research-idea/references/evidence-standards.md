# 证据标准（跨方向通用，定稿前必过）

## 1. 三级证据标签

每个数字/结论必须标来源，只有三种合法标签：

| 标签 | 含义 | 要求 |
|---|---|---|
| **【论文声称】** | 原文/补材写的 | 必须给页码或公式编号 |
| **【可复现基线】** | 官方代码 + 默认参数跑出来的 | 必须给 commit / 参数 / 种子 |
| **【我们的实测】** | 自己在服务器上跑的 | 必须给 `runs/<id>/` 路径，能被第二人复算 |

**禁止第四种标签**（"我们估计""一般认为""文献表明"）——要么补证据，要么删掉。

## 2. 版本作废表（学 01-研究问题陈述 v4 的做法）

每次改稿在开头放一张表：

| 上一版写法 | 本版写法 | 依据 |
|---|---|---|
| "稀有模态不可见" | 降级为"选根 ∧ 领地"合取 | E6verify §3.3（冲突 C2） |

**旧写法一律作废，不删不藏**——半年后你才能分清哪个数是真的。

## 3. 数字的可追溯性

- 论文里的表 → 必须能指回 `runs/index.csv` 的某一行
- 图 → 必须能由 `runs/<id>/` 的原始 CSV 重新画出来
- 若某数字"只能看产物、不能重算" → 明确标注，不允许混进主表

## 4. 表述纪律

| 禁止 | 替代 |
|---|---|
| "显著提升" | "提升 X 个点（5 种子均值 ± std）" |
| "效果很好" | "在 N 个数据集上，M 个优于对照" |
| "理论上保证" | 给出定理编号与前提条件；没证明就写"经验观察" |
| "首次提出" | 必须先扫 C 类空位，否则不用 |

## 5. 构造性反例的额外要求

只写「存在反例」会被一句话打回：**换个参数就没了**。必须给：

| 要求 | 例 |
|---|---|
| 参数窗口 | 「反例成立 ⟺ n/2 ≤ s < n」而不是「s=4 时有反例」 |
| 窗口的精确性 | 窗口内全部复现、窗口外全部不复现（给出两侧证据） |
| 与哪些参数无关 | 「p=0.7 与 p=1.0 同结论 ⇒ 不是纯度阈值挑出来的」 |
| 有无隐藏参数 | 若依赖未报参数，补一个「无该参数」版本，否则作废 |
